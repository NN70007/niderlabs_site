Signature des modèles d'IA : principes et mise en œuvreSigning AI models: principles and implementationFirma de los modelos de IA: principios y aplicaciónSignatur von KI-Modellen: Grundsätze und Umsetzung

La signature des logiciels est une pratique établie de longue date dans les organisations. Les modèles d'IA, en revanche, sont encore souvent introduits par simple téléchargement. Un modèle constitue pourtant une dépendance à part entière, dont le niveau de risque peut excéder celui d'un composant logiciel.

Software signing is a long-established practice within organisations. AI models, by contrast, are still frequently introduced by simple download. A model is nevertheless a dependency in its own right, whose level of risk may exceed that of a software component.

La firma del software es una práctica consolidada desde hace tiempo en las organizaciones. Los modelos de IA, en cambio, se siguen incorporando a menudo mediante una simple descarga. Un modelo constituye, sin embargo, una dependencia de pleno derecho, cuyo nivel de riesgo puede superar el de un componente de software.

Die Signatur von Software ist in Organisationen seit Langem etablierte Praxis. KI-Modelle werden dagegen noch häufig durch einfachen Download eingebracht. Ein Modell ist jedoch eine vollwertige Abhängigkeit, deren Risiko das einer Softwarekomponente übersteigen kann.

Un fichier de modèle n'est pas un contenu passifA model file is not passive contentUn archivo de modelo no es un contenido pasivoEine Modelldatei ist kein passiver Inhalt

Certains formats historiques de modèles, fondés sur le mécanisme de sérialisation « pickle » de Python, permettent l'exécution de code au moment du chargement. Le chargement d'un tel fichier d'origine inconnue équivaut à l'exécution d'un programme d'origine inconnue. Les formats plus récents, tels que safetensors ou GGUF, ne contiennent que des données, ce qui réduit fortement ce risque.

Certain legacy model formats, based on Python's “pickle” serialisation mechanism, allow code to be executed at load time. Loading such a file of unknown origin is equivalent to running a program of unknown origin. More recent formats, such as safetensors or GGUF, contain data only, which greatly reduces this risk.

Determinados formatos históricos de modelos, basados en el mecanismo de serialización «pickle» de Python, permiten la ejecución de código en el momento de la carga. Cargar un archivo de este tipo de origen desconocido equivale a ejecutar un programa de origen desconocido. Los formatos más recientes, como safetensors o GGUF, solo contienen datos, lo que reduce considerablemente este riesgo.

Bestimmte ältere Modellformate, die auf dem Serialisierungsmechanismus „pickle“ von Python beruhen, erlauben die Ausführung von Code beim Laden. Das Laden einer solchen Datei unbekannter Herkunft kommt der Ausführung eines Programms unbekannter Herkunft gleich. Neuere Formate wie safetensors oder GGUF enthalten ausschließlich Daten, was dieses Risiko erheblich verringert.

Un fichier dépourvu de code exécutable n'est pas pour autant sans risque. Un modèle substitué, dégradé ou simplement issu d'une autre version produit des résultats différents. Dans les métiers où le texte engage son auteur, l'identité exacte du modèle à l'origine de chaque résultat doit pouvoir être établie.

A file devoid of executable code is not, however, free of risk. A model that has been substituted, degraded or simply taken from another version produces different results. In professions where a text commits its author, the exact identity of the model behind each result must be capable of being established.

Un archivo desprovisto de código ejecutable no está, sin embargo, exento de riesgo. Un modelo sustituido, degradado o simplemente procedente de otra versión produce resultados distintos. En las profesiones en las que el texto compromete a su autor, debe poder acreditarse la identidad exacta del modelo que ha originado cada resultado.

Eine Datei ohne ausführbaren Code ist deshalb nicht risikofrei. Ein ausgetauschtes, verschlechtertes oder schlicht aus einer anderen Version stammendes Modell liefert andere Ergebnisse. In Berufen, in denen ein Text seinen Verfasser bindet, muss sich die genaue Identität des Modells, das ein Ergebnis erzeugt hat, nachweisen lassen.

Empreinte et signature : deux fonctions distinctesFingerprint and signature: two distinct functionsHuella y firma: dos funciones distintasPrüfsumme und Signatur: zwei verschiedene Funktionen

Ces deux mécanismes répondent à des questions différentes.

These two mechanisms answer different questions.

Estos dos mecanismos responden a preguntas diferentes.

Diese beiden Mechanismen beantworten unterschiedliche Fragen.

  • L'empreinte (SHA-256, par exemple) établit l'identité du fichier avec celui qui est attendu. Elle est suffisante lorsqu'il existe une liste fermée de fichiers connus, obtenue par un canal de confiance.
  • The fingerprint (SHA-256, for example) establishes that the file is identical to the one expected. It is sufficient where there is a closed list of known files, obtained through a trusted channel.
  • La huella (SHA-256, por ejemplo) acredita la identidad del archivo con el esperado. Es suficiente cuando existe una lista cerrada de archivos conocidos, obtenida por un canal de confianza.
  • Die Prüfsumme (zum Beispiel SHA-256) belegt, dass die Datei mit der erwarteten identisch ist. Sie genügt, wenn eine geschlossene Liste bekannter Dateien vorliegt, die über einen vertrauenswürdigen Kanal bezogen wurde.
  • La signature (Ed25519, par exemple) établit que le fichier a été publié par le détenteur d'une clé donnée. Elle permet d'admettre de nouvelles versions sans mise à jour d'une liste, dès lors qu'elles sont signées par la clé attendue.
  • The signature (Ed25519, for example) establishes that the file was published by the holder of a given key. It allows new versions to be accepted without updating a list, provided that they are signed with the expected key.
  • La firma (Ed25519, por ejemplo) acredita que el archivo ha sido publicado por el titular de una clave determinada. Permite admitir nuevas versiones sin actualizar una lista, siempre que estén firmadas con la clave esperada.
  • Die Signatur (zum Beispiel Ed25519) belegt, dass die Datei vom Inhaber eines bestimmten Schlüssels veröffentlicht wurde. Sie erlaubt es, neue Versionen ohne Aktualisierung einer Liste zuzulassen, sofern sie mit dem erwarteten Schlüssel signiert sind.

En pratique, les deux mécanismes se combinent : signature pour les modèles d'un éditeur, liste d'empreintes pour les modèles publics, que l'éditeur ne saurait signer en lieu et place de leur auteur.

In practice, the two mechanisms are combined: signature for a vendor's own models, a list of fingerprints for public models, which the vendor cannot sign in place of their author.

En la práctica, ambos mecanismos se combinan: firma para los modelos de un editor, lista de huellas para los modelos públicos, que el editor no puede firmar en lugar de su autor.

In der Praxis werden beide Mechanismen kombiniert: Signatur für die Modelle eines Herstellers, eine Liste von Prüfsummen für öffentliche Modelle, die der Hersteller nicht anstelle ihres Urhebers signieren kann.

Une vérification préalable au chargementVerification prior to loadingUna verificación previa a la cargaPrüfung vor dem Laden

La vérification n'a de valeur que si elle conditionne le chargement. Le logiciel calcule l'empreinte ou vérifie la signature, puis refuse le fichier en cas d'écart, avec un message explicite et sans possibilité de passer outre. Un contrôle qu'une simple action de l'utilisateur permet de contourner ne constitue pas un contrôle.

Verification has value only if loading is conditional upon it. The software computes the fingerprint or verifies the signature, then rejects the file in the event of a discrepancy, with an explicit message and no possibility of override. A check that a single user action can bypass does not constitute a check.

La verificación solo tiene valor si condiciona la carga. El software calcula la huella o verifica la firma y, en caso de discrepancia, rechaza el archivo con un mensaje explícito y sin posibilidad de omitir el rechazo. Un control que una simple acción del usuario permite eludir no constituye un control.

Die Prüfung hat nur dann einen Wert, wenn das Laden von ihr abhängt. Die Software berechnet die Prüfsumme oder prüft die Signatur und weist die Datei bei einer Abweichung zurück, mit eindeutiger Meldung und ohne Möglichkeit, die Zurückweisung zu übergehen. Eine Kontrolle, die sich durch eine einzige Benutzeraktion umgehen lässt, ist keine Kontrolle.

Pour les modèles publics, la version est également figée : le téléchargement porte sur une révision précise, et non sur la dernière disponible. Le contenu d'un dépôt public peut évoluer ; une révision figée et son empreinte ne le peuvent pas.

For public models, the version is also pinned: the download targets a specific revision, not the latest available. The content of a public repository may change; a pinned revision and its fingerprint cannot.

En el caso de los modelos públicos, la versión también se fija: la descarga se refiere a una revisión concreta, y no a la última disponible. El contenido de un repositorio público puede evolucionar; una revisión fijada y su huella, no.

Bei öffentlichen Modellen wird auch die Version festgeschrieben: Heruntergeladen wird eine bestimmte Revision, nicht die jeweils neueste. Der Inhalt eines öffentlichen Repositorys kann sich ändern; eine festgeschriebene Revision und ihre Prüfsumme können es nicht.

Protection de la clé privéeProtection of the private keyProtección de la clave privadaSchutz des privaten Schlüssels

La valeur d'une signature est celle de la protection de la clé privée. Celle-ci ne doit jamais figurer dans un dépôt de code ni sur une machine exposée. Seule la clé publique est livrée avec le logiciel. Le remplacement de la clé doit être prévu dès la conception, y compris la manière dont le logiciel accordera sa confiance à la nouvelle.

A signature is worth exactly as much as the protection of the private key. That key must never be held in a code repository or on an exposed machine. Only the public key is shipped with the software. Key replacement must be provided for from the design stage, including the way in which the software will come to trust the new key.

El valor de una firma es el de la protección de la clave privada. Esta no debe figurar nunca en un repositorio de código ni en una máquina expuesta. Con el software solo se entrega la clave pública. La sustitución de la clave debe preverse desde el diseño, incluida la forma en que el software otorgará su confianza a la nueva.

Eine Signatur ist genau so viel wert wie der Schutz des privaten Schlüssels. Dieser darf sich niemals in einem Code-Repository oder auf einer exponierten Maschine befinden. Mit der Software wird ausschließlich der öffentliche Schlüssel ausgeliefert. Der Austausch des Schlüssels ist bereits in der Konzeption vorzusehen, einschließlich der Art und Weise, wie die Software dem neuen Schlüssel vertrauen wird.

Étape suivante : la validation par l'organisationThe next step: validation by the organisationEtapa siguiente: la validación por parte de la organizaciónNächster Schritt: Freigabe durch die Organisation

Pour une grande organisation, le dispositif cible associe la signature par l'éditeur de ce qu'il publie et la décision de l'organisation, au moyen de sa propre liste, des modèles autorisés sur ses postes. Il s'agit de la logique de la liste blanche d'applications, étendue aux modèles d'IA.

For a large organisation, the target arrangement combines signature by the vendor of what it publishes with the organisation's own decision, by means of its own list, as to which models are authorised on its workstations. This is the logic of application allow-listing, extended to AI models.

Para una gran organización, el dispositivo objetivo combina la firma por parte del editor de lo que publica con la decisión de la organización, mediante su propia lista, de los modelos autorizados en sus puestos. Se trata de la lógica de la lista blanca de aplicaciones, extendida a los modelos de IA.

Für eine große Organisation verbindet die Zielarchitektur die Signatur des Herstellers für das von ihm Veröffentlichte mit der Entscheidung der Organisation, über eine eigene Liste festzulegen, welche Modelle auf ihren Arbeitsplätzen zugelassen sind. Dies entspricht dem Prinzip der Anwendungs-Positivliste, übertragen auf KI-Modelle.

NiderVoice met en œuvre ces règles : les modèles de NiderLabs sont signés en Ed25519, les modèles publics tels que Whisper sont vérifiés au moyen d'une liste fermée d'empreintes SHA-256, et tout autre fichier est refusé. Voir la page Modèles.

NiderVoice implements these rules: NiderLabs models are signed with Ed25519, public models such as Whisper are verified against a closed list of SHA-256 fingerprints, and any other file is rejected. See the Models page.

NiderVoice aplica estas reglas: los modelos de NiderLabs se firman con Ed25519, los modelos públicos como Whisper se verifican mediante una lista cerrada de huellas SHA-256 y cualquier otro archivo es rechazado. Véase la página Modelos.

NiderVoice setzt diese Regeln um: Die Modelle von NiderLabs sind mit Ed25519 signiert, öffentliche Modelle wie Whisper werden anhand einer geschlossenen Liste von SHA-256-Prüfsummen geprüft, und jede andere Datei wird zurückgewiesen. Siehe die Seite „Modelle“.
